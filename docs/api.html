metric

moonbitstack/moonp8s/metric

The model: kinds, the seven metric types, families, a registry, and the snapshot an exposition is written from. Nothing here reads a clock, opens a socket or writes a byte.

Restart the counter at zero, optionally dating the reset as a new creation time. Use this when a logical process restarts without restarting the program.

02

expo

moonbitstack/moonp8s/expo

The two text formats, their negotiation from an Accept header, and a parser for both. The float and escape rules are the ones a scraper already implements.

Values

fn escape_help(String, Bool) -> String

Escape help text. The compatibility format escapes backslash and newline; OpenMetrics also escapes the double quote, so help text survives a round trip inside a line-oriented document.

fn escape_label_value(String) -> String

Escape a label value: backslash, double quote, and newline are backslash-escaped, every other character passes through as UTF-8.

fn format_float(Double) -> String

Format a float the way the official clients do: +Inf, -Inf, and NaN by name; otherwise the shortest decimal that round-trips, with a .0 on integers and Go's switch to a two-digit exponent once the integer part is longer than six digits (so 1000000.0 is 1e+06, matching what a Prometheus scrape expects to read).

fn negotiate(String) -> Format

Pick a format from an HTTP Accept header. application/openmetrics-text wins when it names a version this library speaks (or names no version); otherwise a scrape gets the compatibility format, which is also the default when the header is absent or unrecognised.

fn openmetrics(Array[@metric.MetricFamily]) -> String

Write families in the OpenMetrics text format, version 1.0.0, ending with the # EOF marker the format requires.

fn parse(String, format? : Format) -> Array[@metric.MetricFamily] raise @metric.Refused

Parse an exposition back into families. The compatibility format is lossy for info and state sets, which it spells as gauges; OpenMetrics keeps them. The format argument selects which spelling conventions to expect, and the same parser accepts both because the syntax is a superset.

fn protobuf(Array[@metric.MetricFamily]) -> Bytes

Write families in the Prometheus protobuf format: a length-delimited stream of io.prometheus.client.MetricFamily messages, the bytes a scraper reads when it answers application/vnd.google.protobuf. It shares the text formats' snapshot, so one scrape is every format. A family is named as the text format declares it, so a counter is &lt;name&gt;_total with its value in the counter field and an info is &lt;name&gt;_info; a histogram keeps its cumulative buckets, sum, and count, its +Inf bucket being the count; a summary keeps its count, sum, and quantiles; a state set is a gauge per state.

let protobuf_content_type: String

The Content-Type an HTTP response should carry for the protobuf format: the metric family the stream holds and the framing of the messages.

fn text(Array[@metric.MetricFamily]) -> String

Write families in the Prometheus text exposition format, version 0.0.4. Counters gain a _total suffix, info becomes a gauge ending in _info, state sets become gauges, and _created, _gcount, and _gsum series are emitted as separate gauge families, as the compatibility format requires.

fn wants_protobuf(String) -> Bool

Whether an Accept header asks for the protobuf format. It does when any part is the media type the protobuf exposition carries; the two text formats are picked out of the header by negotiate, which never returns a protobuf.

multiproc

moonbitstack/moonp8s/multiproc

How several processes' values become one series: the gauge modes, the record a worker's file holds, its bytes, and the merge. Pure data, so it runs on every target.

Values

fn merge(Array[Part]) -> Array[@metric.MetricFamily] raise @metric.Refused

Fold the parts into one set of families.

Counters and summaries add up across processes; histograms add up per bucket and are made cumulative again; a gauge follows its mode. Families come out in the order their first part mentions them, and series in the order they were first seen, so two runs over the same directory write the same bytes.

A family that two files disagree about — a name that is a counter in one process and a histogram in another, or a gauge written under two modes — is refused. The numbers would be meaningless, and a scrape that says so is better than one that quietly picks a side.

The pair of metric and sample is what lets a counter be filed under orders and written as orders_total, and a histogram bucket under orders_seconds and orders_seconds_bucket.

enum Mode

How the values of one gauge from several processes become one series.

A gauge has no natural merge — a counter can be added up, a bucket can be added up, but "requests in flight" from three workers is a policy decision. All and LiveAll keep the processes apart, one series each, labelled pid; the other four collapse them: the smallest, the largest, the sum, or the value set most recently.

The Live spellings mean the same thing at a scrape. They decide what happens when a process exits: mark_dead removes the files of a live mode, and leaves the others, which is what makes a handful of gauges forget a dead worker instead of keeping its last value forever.

fn Part::decode(String, Bytes) -> Self raise @metric.Refused

Decode one worker's file. A file shorter than its header claims is refused rather than half-read: a torn file means a writer that does not write whole files, and guessing at the remainder would report numbers nobody wrote.

fn Part::encode(Self) -> Bytes

The bytes of this part: a four-byte used count, four bytes of padding, then one record per entry — a key length, the key, padding to an eight-byte boundary, the value, and the timestamp, each value a little-endian double.

This is the layout the official clients' multiprocess mode uses, which is the point: a directory of these files is readable by them and by this library alike.

fn Part::file_name(Self) -> String

The name this part is stored under: &lt;kind&gt;_&lt;pid&gt;.db, or gauge_&lt;mode&gt;_&lt;pid&gt;.db for gauges, which is the layout the official clients read and write.

fn Part::name_of(String) -> (String, @metric.Kind, Mode?) raise @metric.Refused

The part a file name announces. A gauge file carries its mode in the name because the mode is a property of how the worker wrote the value, and the scrape has no other way to learn it.
